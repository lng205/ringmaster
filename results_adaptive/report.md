# 自适应冗余算法实验报告

## 1. 实验目的

1. 验证系统能正确估计丢包率并动态调节冗余度
2. 评估自适应算法相比固定冗余的带宽节省效果

## 2. 实验配置

| 参数 | 值 |
|------|-----|
| 视频源 | sintel_trailer_2k_1080p24.y4m |
| 分辨率 | 1920×1080 |
| 帧率 | 24 fps |
| 目标码率 | 4 Mbps |
| 网络延迟 | 20 ms |

### 网络波动设置

```
时间轴: 0s ─────30s─────40s─────70s─────80s─────100s
丢包率:    2%          15%         2%          15%         2%
```

- 总时长: 100 秒
- 低丢包期 (2%): 80 秒 (80%)
- 高丢包期 (15%): 20 秒 (20%)

### 对比方案

| 方案 | 冗余策略 |
|------|----------|
| adaptive | 根据 EWMA 丢包率动态调整 |
| fixed20 | 固定 20% 冗余 |

## 3. 实验结果

### 3.1 带宽与传输统计

| 指标 | 自适应 | 固定20% | 差异 |
|------|--------|---------|------|
| tx_bytes | 49,508,434 | 54,649,975 | **-9.4%** |
| tx_pkts | 35,190 | 38,773 | -9.2% |
| repair_pkts | 2,904 | 6,440 | **-54.9%** |
| retrans_pkts | 5,742 | 4,364 | +31.6% |

### 3.2 视频质量

| 指标 | 自适应 | 固定20% |
|------|--------|---------|
| 解码帧数 | 2,390 | 2,389 |
| 解码率 | 99.6% | 99.5% |

### 3.3 解码延迟

| 指标 | 自适应 | 固定20% |
|------|--------|---------|
| 平均延迟 | 30.8 ms | 22.8 ms |
| P50 | 20 ms | 20 ms |
| P95 | 62 ms | 61 ms |

### 3.4 冗余度变化

自适应方案冗余度范围: **2% - 21%**

```
阶段        观测丢包率    冗余度
─────────────────────────────────
低丢包期    0.03-0.06     0.03-0.04
高丢包期    0.27-0.31     0.08→0.20
恢复期      0.12→0.04     0.13→0.04
```

## 4. 分析

### 4.1 带宽节省

自适应方案在 80% 的低丢包时间内使用 2-4% 冗余，相比固定 20% 大幅减少冗余包发送，总体节省 9.4% 带宽。

### 4.2 重传增加

自适应方案重传包数量高于固定方案 (+31.6%)。原因:
- EWMA 平滑导致冗余度响应滞后
- 高丢包期初期冗余不足，需要重传补救

### 4.3 延迟差异

自适应方案平均延迟略高 (+8ms)，但 P50/P95 与固定方案相近。延迟增加主要来自高丢包期的恢复等待。

## 5. 结论

1. **丢包估计有效**: 算法能检测 2%↔15% 的丢包率变化
2. **冗余调节正确**: 低丢包时 2-4%，高丢包时升至 20%
3. **带宽节省 9.4%**: 冗余包减少 55%
4. **QoS 基本一致**: 解码帧数相同，延迟 P95 相近
5. **权衡**: 以少量重传和平均延迟换取带宽节省
